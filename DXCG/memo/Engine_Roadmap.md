# DXCG 엔진 로드맵

셰도우맵 + Scene/GameObject/Transform 구조까지 끝난 시점에서, 앞으로 뭘 어떤 순서로 할지 정리한 가이드.
최종 목표는 렌더러가 아니라 **게임 엔진**이므로, 기능을 늘리는 것보다 "나중에 얹을 자리를 만드는 것"을 우선한다.

---

## 0. 지금 상태

**되어 있는 것**

- D3D12 기본 파이프라인: Device / CommandQueue / SwapChain / FrameResource(트리플 버퍼링)
- 셰도우맵: 방향광 1개, 2-pass, PCF 비교 샘플러
- 머티리얼: StructuredBuffer + 인덱싱 (bindless 스타일)
- 텍스처: `TextureManager`가 DDS 로드 + SRV 힙 소유, 루트 시그니처에 unbounded 배열 슬롯(t2)까지 준비됨
- 씬 구조: `Transform`(부모-자식 계층) / `GameObject` / `Scene`
- 카메라(FPS 이동), 입력(`InputManager`), 레이 피킹

**아직 안 된 것**

- 텍스처가 실제로 셰이더에서 안 쓰임 (파이프라인은 깔려 있는데 마지막 배선이 빠짐)
- 외부 모델 로딩 없음 (박스/바닥 하드코딩)
- 윈도우 리사이즈 처리 없음
- 컬링/인스턴싱 없음 (의도적으로 보류 — 병목이 보일 때 하기로 함)

---

## 1단계: 미완성인 것 마무리 (짧게, 먼저)

새 기능을 얹기 전에 반쯤 만들어둔 것들을 닫아야 나중에 원인 추적이 쉬워진다. 다 합쳐서 하루 이틀 분량.

### 1-1. 텍스처 배선 완성

`TextureManager`, 루트 시그니처 슬롯, SRV 힙까지 다 만들어놨는데 마지막 세 군데가 비어 있다.

- [ ] `Renderer::LoadTextures()` — 주석 처리된 `LoadTexture(...)` 호출 살리고 실제 DDS 파일 넣기
- [ ] `Renderer::Draw()` 메인 패스 — `SetDescriptorHeaps`에 텍스처 힙 추가, `SetGraphicsRootDescriptorTable(4, ...)` 호출
- [ ] `Default.hlsl` PS — 주석 처리된 `gTextures[...].Sample(...)` 살리고 `mat.DiffuseAlbedo`에 곱하기
- [ ] `InitializeMaterials()` — `DiffuseSrvHeapIndex`를 `-1`이 아니라 `mTextureManger->GetTexture("이름")->SrvHeapIndex`로 채우기

주의: 인덱스가 `-1`(→ UINT로 42억)인 채로 셰이더가 샘플링하면 GPU가 죽고 `Present()`에서 에러가 난다. 이미 한 번 겪은 문제라 인덱스를 반드시 먼저 채울 것.

### 1-2. 노멀 매핑

텍스처가 붙으면 바로 이어서. 탄젠트 공간 변환이 필요하다.

- [ ] `Vertex` 구조체에 `Tangent` 추가 + 입력 레이아웃에 `TANGENT` 추가
- [ ] 지오메트리 생성 시 탄젠트 채우기 (박스/바닥은 손으로 넣어도 됨)
- [ ] `Default.hlsl`에 TBN 행렬 만들어서 노멀맵 샘플값을 월드 공간 노멀로 변환

### 1-3. 자잘한 정리

- [ ] `TextureManager::GetTexture()`가 `.cpp`에서 `inline`으로 정의되어 있음 → 다른 파일에서 호출하는 순간 링커 에러. `inline`을 빼고 `.cpp`에 정의하거나, 헤더로 옮길 것
- [ ] 그림자맵 해상도가 `mClientWidth/mClientHeight`에 묶여 있음 → 2048 같은 고정값으로 분리 (창 크기와 그림자 품질은 별개여야 함)
- [ ] `ShadowMap::OnResize()`가 선언만 있고 구현 없음 → 구현하거나 선언 삭제
- [ ] `mMainLight` raw 포인터로 캐시 중 → `Scene`이 소유하므로, `Scene::GetMainLight()` 같은 접근자로 바꾸는 게 안전

## 2단계: 엔진 골격 (가장 중요)

여기가 "렌더러"와 "엔진"을 가르는 지점. 지금 `Renderer` 클래스가 렌더링 + 윈도우 루프 + 씬 구성 + 카메라 + 입력을 전부 들고 있는데, 이걸 분리하지 않으면 앞으로 뭘 추가하든 계속 `Renderer`에 쌓인다.

### 2-1. Application / Renderer 분리

- [ ] `Application` 클래스 신설: 윈도우 생성, 메시지 루프(`Run()`), 타이머, 리사이즈 처리
- [ ] `Renderer`는 "씬을 받아서 그리는 것"만 담당 — `Run()`, `mTimer`, `mHWnd` 등을 `Application`으로 이동
- [ ] `WinMain`은 `Application`만 만들고 실행

### 2-2. 씬 구성 코드를 Scene으로 이동

- [ ] `Renderer::InitializeRenderItem()` / `InitializeLights()`의 오브젝트 생성 로직을 `Scene::BuildTestScene()` 같은 함수로 이동
- [ ] `Renderer`에는 지오메트리/머티리얼/PSO 같은 **GPU 리소스** 초기화만 남기기
- [ ] 카메라도 `Scene`이 소유하는 쪽이 일관적 (씬의 일부이므로)

### 2-3. 윈도우 리사이즈 처리

지금 `SwapChain::OnResize`가 구현되어 있는데 아무도 호출하지 않는다. 창 크기를 바꾸면 깨진다.

- [ ] `WndProc`의 `WM_SIZE`에서 `Application::OnResize` 호출
- [ ] 스왑체인 버퍼 재생성, 깊이 버퍼 재생성, 뷰포트/시저 갱신, 카메라 종횡비 갱신
- [ ] 리사이즈 전에 `FlushCommandQueue()`로 GPU 작업 완료 대기 (필수)

### 2-4. (선택) 컴포넌트 구조로 확장

`GameObject`가 지금은 `Render`/`LightData` 포인터를 직접 들고 있는데, 종류가 늘어나면(물리, 스크립트, 오디오...) 이 방식은 한계가 온다. 다만 지금 당장은 과하니, 종류가 3~4개로 늘어나는 시점에 도입하는 걸 권장.

---

## 3단계: 에셋 파이프라인

씬 구조가 정리되면 진짜 콘텐츠를 넣을 차례.

- [ ] 모델 로더: Assimp 붙이는 게 제일 빠름 (직접 짜고 싶으면 OBJ부터)
- [ ] 로드한 메시를 `MeshGeometry`/`SubmeshGeometry`에 매핑 (지금 구조가 이미 여러 서브메시를 담을 수 있게 되어 있어 그대로 활용 가능)
- [ ] 모델에 딸린 텍스처/머티리얼을 `TextureManager`/`mMaterials`에 자동 등록
- [ ] 로드한 모델 하나를 `GameObject` 계층으로 펼치기 (모델 노드 트리 → Transform 부모-자식)

여기까지 하면 "임의의 3D 씬을 띄우는 엔진"이 된다.

---

## 4단계: 개발 편의 도구

기능은 아니지만 이후 모든 작업 속도를 좌우한다. 2단계 이후 아무 때나 끼워넣어도 됨.

- [ ] **ImGui 연동** — 라이트 방향, DepthBias, 머티리얼 파라미터를 재빌드 없이 실시간 조정
- [ ] 씬 계층 트리 패널 (GameObject 목록 + Transform 편집)
- [ ] 통계 표시 (FPS, 드로우콜 수, 프레임 타임)
- [ ] 그림자맵 디버그 뷰 (화면 구석에 그림자맵 텍스처 그대로 출력)

마지막 항목은 특히 유용하다. 이번에 그림자 디버깅할 때 그림자맵을 눈으로 볼 수 있었다면 전치 문제를 훨씬 빨리 찾았을 것이다.

---

## 5단계: 렌더링 품질

기반이 갖춰진 뒤 재미있는 부분.

- [ ] 스카이박스 / 큐브맵
- [ ] SSAO (루나 책 셰도우맵 다음 챕터, 지금 파이프라인에 바로 얹을 수 있음)
- [ ] 라이트 여러 개 지원 (지금은 방향광 1 + 포인트광 1 고정 — `NUM_*_LIGHTS` 하드코딩 제거)
- [ ] 포인트 라이트 그림자 (큐브맵 셰도우) — 난이도 있음
- [ ] IBL / 환경 반사
- [ ] 캐스케이드 셰도우맵 (넓은 씬에서 그림자 품질 개선)

---

## 6단계: 최적화 (병목이 보일 때)

**미리 하지 말 것.** 오브젝트가 수백 개가 되어 프레임이 떨어지는 걸 확인한 뒤에 착수한다.

- [ ] 프러스텀 컬링 (`RenderItem::Bounds`가 이미 있으므로 `BoundingFrustum::Intersects`만 붙이면 됨)
- [ ] GPU 인스턴싱 (같은 지오메트리 다수 → 드로우콜 통합)
- [ ] PSO/머티리얼별 드로우콜 정렬로 상태 전환 최소화
- [ ] GPU 프로파일링 도구(PIX) 사용법 익히기

---

## 우선순위 요약

바로 다음에 할 일 순서:

1. **텍스처 배선 완성 + 노멀 매핑** (1단계) — 이미 깔아둔 것 마무리, 눈에 보이는 성과
2. **Application 분리 + 씬 구성 코드 이동** (2단계) — 엔진 골격, 지금 해야 나중이 편함
3. **윈도우 리사이즈** (2-3) — 지금 창 크기 바꾸면 깨지므로 언젠가는 필요
4. **ImGui + 그림자맵 디버그 뷰** (4단계) — 이후 모든 디버깅 속도 향상
5. **모델 로딩** (3단계) — 여기서부터 진짜 콘텐츠

## 디버깅 습관 (이번에 배운 것)

지금까지 겪은 버그들의 패턴이 반복되므로 체크리스트로 남긴다.

- **함수를 만들었으면 호출부가 있는지 확인** — `InitializeLights`, `InitializeDescriptorHeaps`, `BuildDescriptor` 모두 "구현은 했는데 호출을 안 한" 버그였다
- **배열 크기를 늘렸으면 그 배열을 쓰는 쪽의 "개수" 인자도 확인** — 루트 시그니처 파라미터 개수, `InitAsDescriptorTable`의 range 개수
- **CPU 구조체와 HLSL 구조체는 항상 짝으로 수정** — 크기/정렬/상수(`MaxLights`)까지
- **행렬을 상수 버퍼에 올릴 땐 무조건 전치** — 하나만 빠져도 원인 찾기 매우 어려움
- **헤더의 구조체 크기가 바뀌면 전체 재빌드** — 증분 빌드는 멤버 오프셋 불일치를 만든다
- **GPU 크래시는 다음 API 호출에서 드러난다** — `Present()`에서 터졌다고 `Present()`가 원인인 경우는 거의 없다
- **원인이 안 잡히면 격리 테스트** — `CalcShadowFactor`가 `1.0f`를 반환하게 해서 그림자/조명 중 어느 쪽 문제인지 가른 것처럼, 의심되는 경로를 통째로 끊어보는 게 추측보다 빠르다
- **디버그 레이어 출력창을 먼저 볼 것** — 셰이더 컴파일 에러는 `OutputDebugStringA`로 이미 찍히고 있다
